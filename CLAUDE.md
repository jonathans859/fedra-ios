# Fedra for iOS (working name)

A VoiceOver-first Mastodon client for iPhone and iPad. It reuses the Rust core of
[trypsynth/fedra](https://github.com/trypsynth/fedra) (MIT, a Windows client written in
Rust with wxDragon) and puts a native SwiftUI interface on top.

This is an independent project. Upstream isn't involved, so keep their copyright notice
(MIT) and credit "Based on Fedra by Quin Gillespie and Aryan Choudhary" in the README
and the About screen. The public app name isn't decided yet. "Fedra" is only the
working name, so user-facing code reads it from `AppInfo.displayName` (FedraModel),
never from a literal. Bundle ID: `com.jonathan859.fedra`.

GitHub: this repo is `jonathans859/fedra-ios`, the core fork is `jonathans859/fedra`.
**Tasks are tracked in GitHub Issues** (one milestone per M-step). `PLAN.md` holds the
roadmap and the decisions. Close issues as work lands; update PLAN.md only when a
decision changes.

## Priorities (in this order)

1. **VoiceOver accessibility.** Every screen must be fully usable without sight. Test
   every change with VoiceOver on a real device before calling it done.
2. **Usability.** Few swipes to reach content, predictable focus, no surprises.
3. **Clean code.** Small types, clear boundaries, tested logic.

Feature count comes after all three. If a feature can't be made accessible yet, it waits.

## Architecture

```
upstream/          git submodule: OUR FORK of trypsynth/fedra, branch `ios-core`
                   (the only change there: a UI-free `fedra-core` crate, so rebasing
                   on upstream stays cheap)
rust/fedra-ffi/    our crate. It wraps fedra-core with UniFFI and is the only Rust
                   that knows Swift exists.
FedraKit/          Swift package
  FedraCore        generated UniFFI bindings + the XCFramework (builds on macOS only)
  FedraModel       pure Swift: view models, settings, formatting. Depends only on
                   protocols, never on FedraCore directly, so it builds and tests on
                   Windows and Linux.
App/               iOS app target (SwiftUI). Project file generated by XcodeGen (project.yml)
```

Rules:
- **Upstream code stays upstream.** Edits in `upstream/` are limited to moving code into
  `fedra-core` and removing UI coupling (wxDragon, wx_utils, live_region, rodio, tray, and
  so on). Keep those commits small and mechanical so they rebase easily, and never add
  iOS features there.
- **The FFI surface is small and async.** UniFFI exports coarse operations
  (`load_timeline`, `post`, `favourite`, ...) and plain records. Don't export Rust
  internals. Blocking Rust calls must never run on the main actor.
- **Rust owns the protocol and the rendering logic** (Mastodon API, HTML-to-text, post
  templates via minijinja, filters). **Swift owns UI, state, persistence, audio and
  the Keychain.**
- Secrets (access tokens, client secrets) go in the Keychain only, never in
  UserDefaults or a config file. Upstream keeps them in its JSON config, and we don't
  copy that.

## Accessibility rules

Apply the `swift-accessibility` skill (~/.claude/skills) and the following:
- One post = one VoiceOver element. Its label comes from the user's post template (the
  same idea as Fedra's templates). Secondary actions (reply, boost, favourite, bookmark,
  open links, view profile, view thread, ...) go in `.accessibilityAction(named:)`
  custom actions, never only in context menus or swipe actions.
- Mark section titles with `.isHeader`. Expose timelines, links and mentions to the rotor
  where it helps.
- Announcements (`AccessibilityNotification.Announcement`) are only for results the user
  didn't cause with their focus. Make them rare, short and queued.
- Refreshing or streaming new posts must never move VoiceOver focus or the reading
  position.
- Dynamic Type everywhere, semantic fonts only, and layouts must work at AX5.
- Sound cues and haptics are optional extra feedback and never the only signal.
- Hardware keyboard (iPad and iPhone): Fedra-style shortcuts via `.keyboardShortcut` /
  `UIKeyCommand`. See the `swift-hardware-keyboard-capture` skill.

## Swift conventions

- Swift 6 language mode, strict concurrency, iOS 18+, iPhone + iPad.
- SwiftUI + Observation (`@Observable`). Settings follow the `swift-observable-settings`
  skill. Never assign to a property inside its own `didSet`.
- View models are `@MainActor`. Calls into the core are `async`, and the work runs off
  the main actor.
- No force unwraps, no `try!`, no singletons except the composition root in `App`.
- English only (no localization planned). Still write whole sentences with
  interpolation rather than concatenated fragments, and format dates and numbers
  with `.formatted()`, so VoiceOver reads them naturally.
- Indentation: tabs (same as upstream, enforced by `.editorconfig`).
- Tests use Swift Testing (`@Test`). Logic in `FedraModel` must be testable with a fake core.

## Rust conventions

- Follow upstream's style in `upstream/`: tabs, `cargo +nightly fmt`, and clippy with
  pedantic + nursery as errors.
- `rust/fedra-ffi` uses the same lint level.

## Building

- Development happens on **Windows with no Mac**. Locally: `cargo test` for Rust, and
  `swift test` for `FedraKit/FedraModel` (see the `swift-windows-toolchain` skill).
- The XCFramework, the app, signing and TestFlight upload run on GitHub Actions macOS
  runners (see the `swift-cicd` skill). The apple-ci shared workflow has no pre-build
  hook, so see PLAN.md for how the Rust build runs before Xcode.
- Testing on a real iPhone goes through TestFlight.

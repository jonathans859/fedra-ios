# Fedra for iOS (working name)

A VoiceOver-first Mastodon client for iPhone and iPad, written entirely in Swift.

The design comes from [Fedra](https://github.com/trypsynth/fedra) (MIT), an accessible
Windows Mastodon client by Quin Gillespie and Aryan Choudhary: post templates that
decide what the screen reader reads, sound cues, keyboard-first use. **We don't use
their code as a dependency.** Upstream is a reference for behaviour and wording.
Where we port logic from it (default templates, HTML-to-text rules, template
variables), credit them in the README, the LICENSE and the About screen. This is an
independent project and upstream isn't involved.

The public app name isn't decided yet. "Fedra" is only the working name, so
user-facing code reads it from `AppInfo.displayName` (FedraModel), never from a
literal. Bundle ID: `com.jonathan859.fedra` (fixed once the App Store Connect record
exists).

GitHub: `jonathans859/fedra-ios`. **Tasks are tracked in GitHub Issues** (one
milestone per M-step). `PLAN.md` holds the roadmap and the decisions. Close issues as
work lands, and update PLAN.md only when a decision changes.

## Priorities (in this order)

1. **VoiceOver accessibility.** Every screen must be fully usable without sight. Test
   every change with VoiceOver on a real device before calling it done.
2. **Usability.** Few swipes to reach content, predictable focus, no surprises.
3. **Clean code.** Small types, clear boundaries, tested logic.

Feature count comes after all three. If a feature can't be made accessible yet, it waits.

## Architecture

```
FedraKit/            Swift package, platform-neutral: builds and tests on Windows,
                     Linux and macOS with plain SwiftPM
  FedraAPI           Mastodon REST client: Codable models, endpoints, OAuth calls,
                     pagination, errors. Foundation only.
  FedraModel         depends on FedraAPI: HTML-to-text, the template engine
                     (Fedra-compatible syntax), formatting, settings, view models
App/                 iOS app target (SwiftUI): views, Keychain, ASWebAuthenticationSession,
                     audio, haptics, keyboard. Project generated by XcodeGen (project.yml)
```

Rules:
- **Nothing Apple-only in FedraKit.** No UIKit, SwiftUI, Security, AuthenticationServices
  or AVFoundation there. Those live in `App/` behind protocols that FedraKit defines. The
  Windows build is the enforcement, so run `swift test` before every commit.
- **Networking goes through a transport protocol** (`HTTPTransport`). The URLSession
  implementation needs `import FoundationNetworking` on Linux and Windows
  (`#if canImport(FoundationNetworking)`). Tests use a fake transport with JSON fixtures
  and never touch the network.
- **Template compatibility with Fedra for Windows.** Same `{{ var }}` / `{% if %}` syntax,
  same variable names, same defaults, so users can copy templates between the two apps.
- Secrets (access tokens, client secrets) go in the Keychain only, never in UserDefaults
  or a file.

## Accessibility rules

Apply the `swift-accessibility` skill (~/.claude/skills) and the following:
- One post = one VoiceOver element. Its label comes from the user's post template.
  Secondary actions (reply, boost, favourite, bookmark, open links, view profile, view
  thread, ...) go in `.accessibilityAction(named:)` custom actions, never only in
  context menus or swipe actions.
- Mark section titles with `.isHeader`. Expose timelines, links and mentions to the rotor
  where it helps.
- Announcements (`AccessibilityNotification.Announcement`) are only for results the user
  didn't cause with their focus. Make them rare, short and queued.
- Refreshing or streaming new posts must never move VoiceOver focus or the reading
  position.
- Dynamic Type everywhere, semantic fonts only, and layouts must work at AX5.
- Sound cues and haptics are optional extra feedback and never the only signal.
- Hardware keyboard (iPad and iPhone): Fedra-style shortcuts via `.keyboardShortcut` /
  `UIKeyCommand`. See the `swift-hardware-keyboard-capture` skill.

## Swift conventions

- Swift 6 language mode, strict concurrency, iOS 18+, iPhone + iPad.
- `async/await` throughout. Model types are `Sendable` value types.
- SwiftUI + Observation (`@Observable`). Settings follow the `swift-observable-settings`
  skill. Never assign to a property inside its own `didSet`.
- View models are `@MainActor`.
- No force unwraps, no `try!`, no singletons except the composition root in `App`.
- No third-party dependencies without asking first.
- English only (no localization planned). Still write whole sentences with
  interpolation rather than concatenated fragments, and format dates and numbers
  with `.formatted()`, so VoiceOver reads them naturally.
- Indentation: tabs (enforced by `.editorconfig`).
- Tests use Swift Testing (`@Test`).

## Building

- Development happens on **Windows with no Mac**. Locally: `cd FedraKit && swift test`
  (see the `swift-windows-toolchain` skill).
- CI: Linux runs `swift test`, and macOS builds the app. Signing and TestFlight go
  through apple-ci (see the `swift-cicd` skill).
- Testing on a real iPhone goes through TestFlight.
